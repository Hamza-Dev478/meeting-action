# Submitting your work

## Repository

Create a separate repository. When this challenge is public, you can use its template feature or copy the materials into a new repository. A public fork makes your work public; choose a private repository if you prefer and grant your interviewers access.

Do not open a solution pull request against the challenge repository or post your submission in a public issue. Send the URL through the channel agreed with your interviewer. For an independent attempt, no submission is necessary.

Keep the exercise materials under `challenge/` if you want your implementation README at the root. Preserve attribution or links for reused materials as appropriate to their licenses. Your implementation remains yours.

## Checklist

- [ ] Rails API, PostgreSQL persistence, and Flutter app source.
- [ ] Setup instructions with runtime versions, dependency installation, database setup/seeds, API and mobile launch commands, and test commands.
- [ ] Instructions for connecting the simulator/emulator to the local API, including the API base URL configuration.
- [ ] Fictional seed users for two organizations and an explanation of development authentication.
- [ ] `.env.example` or equivalent with placeholders, plus fake-provider configuration that requires no secrets.
- [ ] One real provider adapter; label it tested, untested, or blocked, and explain why.
- [ ] Focused tests and actual results, with skipped or blocked checks clearly identified.
- [ ] `AI_WORKLOG.md`, `EVALUATION.md`, and `ARCHITECTURE.md`, using the [templates](templates/).
- [ ] A demo of approximately three minutes, attached privately or linked in the submission.
- [ ] Active work time, setup time, known gaps, and the next three improvements.

Never include credentials, private account information, customer data, or unrelated AI chat history. Selected AI excerpts are enough; full account exports and continuous screen recording are not required. If you accidentally expose a credential, revoke it—deleting the visible file is not sufficient.

## Live review: 60 minutes

- **10 minutes:** run the core flow with fresh synthetic notes.
- **15 minutes:** inspect selected code and AI-workflow evidence.
- **20 minutes:** make one small cross-stack change. AI tools remain available.
- **10 minutes:** discuss retries, request failures, and older mobile clients.
- **5 minutes:** explain your next priorities.

You do not need to memorize framework APIs. You should be able to find the relevant code, explain its behavior, use tools effectively, and verify a change.
