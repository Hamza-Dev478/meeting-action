# AI Fullstack Builder Challenge

**Build with AI. Verify the result. Own the system.**

A time-boxed Rails + Flutter engineering exercise for builders who can take a feature from data model to mobile interface—and explain the decisions behind it.

Build **Meeting → Action**: a small app that turns meeting notes into AI-proposed action items which a person reviews before accepting.

| | |
| --- | --- |
| Time | 4–6 hours of active work, then a 60-minute live review |
| Stack | Rails, PostgreSQL, Flutter |
| AI tools | Expected and encouraged; choose your tools and models |
| What matters | Working behavior, judgment, verification, and ownership |
| Deliverable | Your own repository, a short demo, tests, and evidence of AI use |

## Start here

1. Read the [assignment](CHALLENGE.md), [assessment rubric](RUBRIC.md), and [submission guide](SUBMISSION.md).
2. Create your own repository from these materials. This repository contains the exercise, not a runnable starter or reference implementation.
3. Copy the [evidence templates](templates/) to the root of your submission repository.
4. Build the smallest complete flow. Use the [synthetic evaluation cases](fixtures/evaluation-cases.json).
5. Stop at six hours. Record what works, what does not, and what you would do next.

Before starting a hiring submission, agree with your interviewer on the submission channel, deadline, AI-provider budget, and setup readiness. If you are trying this independently, you can use a local model or your own capped provider account. No purchase is required to read or attempt the exercise.

## What this exercise assesses

- **AI-assisted engineering:** context selection, useful delegation, review, and independent verification.
- **End-to-end delivery:** Rails API, persistence, and a real Flutter client.
- **AI feature quality:** grounded extraction, structured output validation, and failure handling.
- **System ownership:** access boundaries, retries, mobile compatibility, and operational tradeoffs.

We do not score prompt volume, generated lines of code, premium tool subscriptions, or visual polish. You may use documentation, libraries, and existing scaffolds; disclose material reused code and follow its license.
